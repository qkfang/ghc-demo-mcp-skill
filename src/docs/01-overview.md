# 1. System Overview

## 1.1 What the application does

The legacy MuleSoft application — `bookmyshow` (groupId `com.mycompany`,
version `1.0.0-SNAPSHOT`) — is a small **movie ticket booking API**. It allows
clients to:

1. **List currently bookable movies** — every movie row in `movie_table` that
   still has at least one seat available (`m_available > 0`).
2. **Book a number of tickets for a given movie** — validating that enough
   seats remain, computing a tiered price, persisting the order, decrementing
   availability, and returning the freshly created order row.

There is no authentication, no caller identity, no payment processing, and no
seat-selection logic. A "ticket" is simply a unit of `m_available` on the
movie row and a row in `order_table`.

|---|---|---|
| Mule Runtime | `4.4.0` (minimum) | `mulesoft/mule-artifact.json`, `mulesoft/pom.xml` (`app.runtime`) |

| MUnit version | `2.3.6` | `mulesoft/pom.xml` |
| Deployment target | CloudHub (Anypoint) | `mulesoft/pom.xml` `<cloudHubDeployment>` block |

The build also pulls a RAML API definition from Anypoint Exchange:

```
dd352549-b3e6-4dd6-b86f-85ed018825af:movie:1.0.0:raml:zip
```

The RAML file is not committed to this repository; APIKit resolves it from
Exchange at build time. As a result, the canonical contract (data types,
required parameters, response examples) cannot be inspected directly from
source — see [`08-migration-notes.md`](./08-migration-notes.md).

## 1.3 High-level architecture

```
                +-------------------------------+
                |     HTTP client (browser /    |
                |     curl / front-end)         |
                +---------------+---------------+
                                |
                                v
       +-------------------------------------------------+
       |  Mule HTTP listener  (host 0.0.0.0, port 8081)  |
       |  paths: /api/*  and  /console/*                 |
       +-------------------------------+-----------------+
                                       |
                                       v
       +-------------------------------------------------+
       |   APIKit router (movie-config, RAML 1.0.0)      |
       |   Routes to flow named after RAML method+path:  |
       |     GET  /movies         -> GetMovies           |
       |     POST /movies/{m_id}  -> BookTickets         |
       +------+---------------------------+--------------+
              |                           |
              v                           v
   +----------------------+   +-------------------------------+
   | GetMovies flow       |   | BookTickets flow              |
   |  - SELECT movies     |   |  - SELECT availability        |
   |  - JSON transform    |   |  - Validate availability      |
   |  - Log               |   |  - INSERT order               |
   |                      |   |  - UPDATE movie availability  |
   |                      |   |  - SELECT latest order        |
   |                      |   |  - JSON transform             |
   +----------+-----------+   +---------------+---------------+
              \                              /
               \                            /
                v                          v
              +---------------------------------+
              |  MySQL database (remotemysql)   |
              |    movie_table, order_table     |
              +---------------------------------+
```

The `console` flow (`/console/*`) exposes the APIKit console UI for the same
`movie-config`, which renders the RAML.

even though MUnit is on the classpath.

## 1.5 What is **not** in scope of this application

These are deliberately listed so that the migration target does not over-build:

- **Authentication / authorisation** — the listener is anonymous, no policy is
  configured in source.
- **Payments** — pricing is computed but no payment provider is invoked.
- **Seat selection / seat map** — only an integer ticket count is tracked.
- **Customer / user records** — `order_table` is referenced only by
  `m_id`, `no_tickets`, `price`; there is no user identifier in the order
  insert. See `03-business-rules.md`.
- **Idempotency / retry** — no idempotency key is used; repeated POSTs will
  insert repeated orders.
- **Search / pagination** — `GET /movies` returns all available rows in one
  shot.
